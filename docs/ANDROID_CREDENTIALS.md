# Android signing (same keystore for Play Console)

Use the **same** keystore as your previous releases so the uploaded AAB matches the SHA-1 fingerprint Google Play expects.

---

## Option A: EAS-managed credentials (recommended if you already built with EAS)

Your project is configured to use **remote** credentials for production builds. EAS stores one keystore per project; as long as you don’t regenerate it, new builds use the same key.

### Do this

1. **Do not regenerate credentials**  
   When running `eas build` or `eas credentials`, never choose “Generate new keystore” for this app. Use “Use existing” or let EAS use the stored credentials.

2. **Build the AAB**
   ```bash
   eas build -p android --profile production
   ```

3. **Download the `.aab`** from the build page and upload it to Google Play Console. The SHA-1 will match the expected fingerprint.

### If you already regenerated by mistake

- You cannot revert to the old EAS-managed key. You’ll need to **reset the upload key** in Play Console (Setup → App integrity → App signing) and follow Google’s flow to register the new key.
- For future builds, use that new key only (either via EAS or local keystore) and don’t regenerate again.

---

## Option B: Local keystore (when you have the original `.jks` / `.keystore`)

If you have the keystore file you used for the first successful upload (e.g. `tola-upload-key.jks`), you can point EAS at it so every build uses that key.

### 1. Put the keystore in the project (do not commit it)

Example:

- Create a folder, e.g. `android/keystores/` (or use any path you prefer).
- Put your keystore file there, e.g. `tola-upload-key.jks`.  
- Keystore files are already ignored by `.gitignore` (`*.jks`, `*.keystore`).

### 2. Create `credentials.json` in the project root (do not commit it)

Copy from `credentials.json.example` and fill in real values:

```json
{
  "android": {
    "keystore": {
      "keystorePath": "android/keystores/tola-upload-key.jks",
      "keystorePassword": "YOUR_KEYSTORE_PASSWORD",
      "keyAlias": "YOUR_KEY_ALIAS",
      "keyPassword": "YOUR_KEY_PASSWORD"
    }
  }
}
```

- `keystorePath`: path to the `.jks` or `.keystore` file (relative to project root or absolute).
- Replace the placeholders with the passwords and alias you used when creating the keystore.  
- `credentials.json` is in `.gitignore`; keep it local and never commit it.

### 3. Build with the “local” profile

```bash
eas build -p android --profile production-local
```

The `production-local` profile uses `credentialsSource: "local"`, so EAS will use your `credentials.json` and thus the same keystore every time.

### 4. Upload the new `.aab` to Play Console

The bundle will be signed with your original key; the SHA-1 will match what Play expects.

---

## Finding your keystore

- **EAS:** If you never downloaded it, the keystore lives on EAS servers. Use Option A and don’t regenerate.
- **Local:** Check common places: project folder, `~/keystores`, Downloads, or the machine/backup where you first built the app that was accepted by Play.
- **Expo classic / old builds:** Sometimes named like `release.keystore` or `upload-key.jks` in the project or in a backup.

---

## Summary

| Situation | Action |
|----------|--------|
| Built before with EAS and didn’t regenerate | Use `eas build -p android --profile production` (Option A). |
| You have the original `.jks` / `.keystore` | Use `credentials.json` + `production-local` profile (Option B). |
| Lost key and already uploaded a build signed with a new key | Reset upload key in Play Console (Setup → App integrity → App signing). |
